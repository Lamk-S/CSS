Módulo A01 · Arquitectura de Selectores

Modern Selectors: :is(), :where(), :not() y :has()

Domina las pseudo-clases funcionales que transformaron la arquitectura CSS moderna. Reduce especificidad con :where(), agrupa sin repetir con :is(), filtra con :not() complejo y estiliza contenedores según sus hijos con :has().

1. :is() — Agrupación inteligente y tolerante a fallos

Permite agrupar listas de selectores evitando la repetición de ancestros comunes. Además, es una lista tolerante a errores: si un selector de la lista es inválido, el navegador ignora solo ese elemento y aplica los demás. 

/* Antes: repetición de contexto */
.card h2, .card h3, .card h4 {
  color: var(--color-text-strong);
}

/* Ahora: limpio, escalable y tolerante a errores */
.card :is(h2, h3, h4) {
  color: var(--color-text-strong);
}

/* Tolerancia a fallos: aunque ::selector-invalido falle, h1 y h2 se aplican */
:is(h1, h2, ::selector-invalido) {
  line-height: 1.2;
}

Cálculo de Especificidad

:is() adopta la especificidad del argumento más específico de su lista. Por ejemplo, :is(h1, #hero, .title) tendrá especificidad de ID (1,0,0) incluso cuando coincida con un simple <h1>. Si buscas especificidad cero, utiliza :where().

2. :where() — Especificidad cero para Resets y Sistemas

Comparte la misma sintaxis que :is(), pero su especificidad siempre es (0,0,0). Es el estándar recomendado para hojas base, resets y librerías de componentes que deben ser fáciles de sobrescribir. 

/* Reset base con especificidad 0: nunca genera conflictos */
:where(h1, h2, h3, h4, p, ul, ol) {
  margin: 0;
  padding: 0;
}

/* Cualquier clase simple gana automáticamente sin importar el orden */
.title {
  margin-bottom: 1rem; /* Especificidad (0,1,0) > (0,0,0) */
}

/* Comparativa de peso */
:where(h1, h2) { /* (0,0,0) */ }
h1             { /* (0,0,1) - gana sobre :where() */ }
:is(h1, h2)    { /* (0,0,1) - empata con h1 */ }

3. :not() moderno — Negación con listas y selectores complejos

En Selectors Level 4, :not() acepta listas separadas por comas y selectores complejos (descendientes, atributos o pseudo-clases encadenadas), funcionando como un filtro de exclusión preciso. 

/* Exclusión múltiple en una sola declaración */
button:not(.primary, .ghost, [disabled]) {
  border-color: #ef4444;
}

/* Cards que NO contienen una imagen */
.card:not(:has(img)) {
  padding-top: 1.5rem;
}

/* Todos los ítems excepto el primero y el último */
li:not(:first-child, :last-child) {
  border-block: 1px solid var(--color-border);
}

/* Validación UX sin JavaScript: campo con texto, sin foco e inválido */
input:not(:placeholder-shown):not(:focus):invalid {
  border-color: #ef4444;
}

4. :has() — Selector relacional (Parent & Sibling Selector)

Permite estilizar un elemento padre (o un hermano anterior) en función de sus descendientes o de su estado. Elimina la necesidad de clases modificadoras redundantes en el HTML o listeners en JavaScript.

Patrones fundamentales de :has()

/* 1. Parent selector: cambia el layout si el padre contiene una imagen */
.card:has(> img) {
  display: grid;
  grid-template-columns: 120px 1fr;
}

/* 2. Estado de formulario: reacciona si algún campo interno es inválido */
form:has(:invalid) {
  border-color: #ef4444;
}

/* 3. Previous sibling selector: estiliza un h2 solo si le sigue un subtítulo */
h2:has(+ .subtitle) {
  margin-bottom: 0.25rem;
}

5. Arquitectura combinada (Zero-Modifier Components)

Al combinar los cuatro selectores, los componentes UI se vuelven autónomos: el HTML solo declara el contenido y el CSS infiere la variante visual sin clases modificadoras (--with-badge, --has-image). 

/* Botones sólidos que contienen un icono SVG */
button:not(.ghost):has(> svg) {
  padding-inline-start: 2.25rem;
}

/* Bloquea visualmente el botón de envío si hay errores y el usuario ya escribió */
form:has(:invalid):not(:has(:placeholder-shown)) button[type="submit"] {
  opacity: 0.5;
  pointer-events: none;
}

6. Rendimiento y Soporte en Navegadores

  • Acota el alcance de :has(): Evita selectores globales costosos como body:has(...) o *:has(*) que obligan al motor a reevaluar todo el árbol DOM ante cada mutación. Utiliza el combinador de hijo directo (.card:has(> img)) siempre que sea posible.
  • Soporte en producción (Baseline): :is(), :where(), :not() (Nivel 4) y :has() forman parte de CSS Baseline con soporte nativo en Chrome, Edge, Safari y Firefox.
  • Regla mental de uso: :where() para resets → :is() para agrupar → :not() para excluir → :has() para lógica relacional.
