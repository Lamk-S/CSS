Módulo A04 · Cascade Control & Architecture

@layer, @scope y Arquitectura

Pon fin a las guerras de especificidad y a la fuga de estilos globales. @layer te otorga control explícito sobre la prioridad de la cascada, @scope encapsula reglas dentro de un sub-árbol del DOM sin herramientas de compilación, y combinados con Design Tokens estructuran sistemas escalables.

1. @layer — Control explícito de la cascada

En CSS clásico, un selector con ID (#nav .link) siempre vence a una clase (.link-active), obligando a recurrir a !important o selectores artificialmente largos. Con Cascade Layers, el orden en que declaras las capas determina qué regla gana, sin importar la especificidad de los selectores internos.

Declaración de jerarquía: La última capa declarada gana

/* 1. Define el orden de prioridad en la primera línea */
@layer reset, base, tokens, components, utilities;

/* 2. Cada capa puede poblarse en cualquier orden de archivo */
@layer reset {
  * { margin: 0; box-sizing: border-box; }
}

@layer base {
  body { font-family: system-ui, sans-serif; line-height: 1.6; }
}

@layer components {
  .btn { background: #2563eb; color: white; padding: 0.6rem 1rem; }
  /* Aunque use un ID (1,0,0), pierde contra la capa utilities */
  #header .btn { background: #dc2626; }
}

@layer utilities {
  /* Especificidad baja (0,1,0), pero gana sin necesidad de !important */
  .bg-emerald { background: #16a34a; }
  .hidden { display: none; }
}

Regla fundamental: Los estilos declarados fuera de cualquier @layer tienen mayor prioridad que los estilos dentro de capas. Asimismo, el uso de !important invierte el orden de prioridad entre capas.

Demo en vivo: Una clase en @layer utilities vence a un #id en @layer components

Este elemento tiene id="test-id" (rojo en @layer components, especificidad 1,0,0) y class="utility-card" (verde en @layer utilities, especificidad 0,1,0). Gana el verde sin usar !important. 
@layer reset, tokens, base, components, utilities;

@layer components {
  #test-id { background: #fecaca; color: #dc2626; } /* (1,0,0) */
}

@layer utilities {
  .utility-card { background: #dcfce7; color: #15803d; } /* (0,1,0) — Gana por capa */
}

Sub-capas anidadas e importación de terceros

/* Organización modular mediante capas anidadas */
@layer components {
  @layer buttons {
    .btn { /* ... */ }
  }
  @layer cards {
    .card { /* ... */ }
  }
}

/* Encapsula librerías externas en una capa de baja prioridad */
@import url("normalize.css") layer(reset);
@import url("vendor-ui.css") layer(vendor);

2. @scope — Encapsulamiento nativo sin build tools

Al escribir .card h2, la regla desciende indefinidamente y contamina cualquier <h2> dentro de subcomponentes anidados. La regla @scope permite fijar una raíz de alcance y, opcionalmente, un límite inferior (donut scope) donde los estilos dejan de aplicarse.

Sintaxis: Raíz de alcance y límite inferior (to)

/* Alcance acotado: afecta a .card, pero se detiene al llegar a .card-slot */
@scope (.card) to (.card-slot) {
  :scope {
    background: #ffffff;
    border-radius: 12px;
    padding: 1.25rem;
  }

  h2 {
    color: #1d4ed8;
    font-size: 1.15rem;
  }
}

  :scope { border: 2px solid #3b82f6; background: #eff6ff; }
  h2 { color: #1d4ed8; background: #dbeafe; padding: 0.35rem 0.65rem; border-radius: 6px; }
  p  { color: #1e40af; }
}

Matriz de decisión: Cuándo usar cada herramienta moderna

Herramienta Propósito arquitectónico Ejemplo
@layer Ordenar la prioridad global de la cascada @layer reset, base, components, utilities;
@scope Aislar estilos a un fragmento DOM con límite superior e inferior @scope (.card) to (.slot) { h2 { ... } }
:has() Adaptar un contenedor según sus descendientes o estado .card:has(> img) { ... }
:where() Aplicar reglas base con especificidad cero (0,0,0) :where(h1, h2, p) { margin: 0; }

3. Arquitectura Moderna — Layers + Scope + Tokens

Al integrar @layer, @scope y Design Tokens en una misma hoja de estilos, obtienes un sistema predecible que escala desde una landing page hasta un Design System empresarial.

Estructura base de arquitectura escalable

/* 1. Jerarquía explícita de capas */
@layer reset, tokens, base, components, utilities;

/* 2. TOKENS — Fuente única de verdad */
@layer tokens {
  :root {
    --color-primary: #2563eb;
    --radius-md: 12px;
  }
}

/* 3. BASE — Tipografía y elementos semánticos sin clases */
@layer base {
  body { font-family: system-ui, sans-serif; background: #f8fafc; }
}

/* 4. COMPONENTS — Encapsulados con @scope */
@layer components {
  @scope (.arch-card) {
    :scope { background: #ffffff; border-radius: var(--radius-md); padding: 1.25rem; }
    h3 { margin-bottom: 0.5rem; }
  }
}

/* 5. UTILITIES — Alta prioridad de capa con baja especificidad */
@layer utilities {
  :where(.hidden) { display: none; }
}

Checklist de Arquitectura Frontend

Evalúa tu hoja de estilos: ¿Están tus reglas organizadas en @layer? ¿Tus resets combinan :where() dentro de @layer reset? ¿Tus componentes complejos acotan su alcance con @scope para evitar fugas? ¿Eliminaste la necesidad de !important en tus utilidades? Si cumples estos cuatro puntos, tu CSS es escalable por diseño.

4. Bonus: CSS Nesting nativo + @layer

El anidamiento nativo (&) forma parte del estándar CSS moderno y se integra directamente con @layer, :has() y @scope sin necesidad de preprocesadores. 

@layer components {
  .card {
    background: #ffffff;
    border-radius: 12px;
    padding: 1.5rem;

    & h3 {
      margin: 0 0 0.5rem;
      color: #0f172a;
    }

    &:has(> img) {
      display: grid;
      grid-template-columns: 100px 1fr;
      gap: 1rem;
    }

    @scope (&) to (.card-footer) {
      :scope { border: 1px solid #e2e8f0; }
    }
  }
}
