Módulo A02 · Design Systems & Architecture

Design Tokens & Theming

Transforma valores aislados en un sistema escalable. Domina @property (CSS Houdini) para variables tipadas y animables, color-mix() para paletas dinámicas, light-dark() y una arquitectura de temas con data-theme + prefers-color-scheme.

1. Qué son los Design Tokens y por qué importan

Un Design Token es una variable semántica que almacena una decisión de diseño: color, escala tipográfica, espaciado, radio o elevación. En lugar de dispersar #2563eb por decenas de archivos, referencias var(--color-primary). Si la identidad visual cambia, actualizas una sola definición en :root.

  • Single Source of Truth: Única fuente de verdad compartida entre diseño y código.
  • Generación dinámica: Permiten derivar estados (hover, soft, bordes) matemáticamente con color-mix().
  • Theming nativo: Alternancia instantánea entre modo claro y oscuro sin duplicar selectores de componentes.

Tokens semánticos activos en este documento

--color-primary
--color-primary-soft
--color-surface
--color-bg
:root {
  /* 1. Primitivos (valores crudos) */
  --blue-500: #2563eb;

  /* 2. Semánticos (intención de uso) */
  --color-primary: var(--blue-500);
  --color-primary-soft: color-mix(in srgb, var(--color-primary) 12%, transparent);
  --radius-md: 14px;
  --shadow-card: 0 4px 20px rgba(15, 23, 42, 0.06);
}

2. @property — Variables tipadas y animables

Por defecto, una Custom Property estándar es tratada por el navegador como una cadena de texto sin tipo. Al desconocer si representa un ángulo, un color o una longitud, el motor no puede interpolar valores intermedios. La regla @property registra la variable con una sintaxis estricta, herencia y valor inicial. 

@property --angle {
  syntax: "<angle>"; /* Otros tipos: <color>, <length>, <percentage>, <number> */
  inherits: false;
  initial-value: 0deg;
}

@property --primary-hue {
  syntax: "<number>";
  inherits: true;
  initial-value: 221;
}

Demo: Borde cónico animado (impulsado por @property)

Sin @property, un conic-gradient no puede animar su ángulo inicial. Al tipar --angle como <angle>, el navegador interpola de 0deg a 360deg de forma continua.

Card con @property --angle

El borde gira suavemente porque --angle está registrado como tipo angular.

Regla de Arquitectura

Registra con @property cualquier token que necesites transicionar o animar: ángulos en gradientes, paradas de color o valores numéricos. Además, aporta validación: si alguien asigna un valor inválido al token, el navegador revierte al initial-value en lugar de romper la regla.

3. color-mix() y light-dark() — Paletas sin hardcode

Las funciones modernas de color eliminan la necesidad de preprocesadores (Sass/Less) para calcular tintes, sombras o variantes de tema.

color-mix() — Escala tonal derivada

Mezcla el token primario contra la superficie activa en el espacio de color indicado.

--color-primary-soft: color-mix(in srgb, var(--color-primary) 14%, transparent);
--color-primary-hover: color-mix(in srgb, var(--color-primary) 85%, black);

light-dark() — Resolución dual en una línea

Evalúa automáticamente el valor claro u oscuro según el color-scheme activo en el contexto.

:root {
  color-scheme: light dark;
}

.card {
  background: light-dark(#ffffff, #1e293b);
  color: light-dark(#0f172a, #e2e8f0);
  border-color: light-dark(#e2e8f0, #334155);
}

4. Arquitectura de Theming: data-theme + prefers-color-scheme

Un sistema de temas resiliente en producción combina tres niveles de prioridad:

  1. Tokens duales con light-dark(): Declara ambos esquemas desde el inicio en :root mediante color-scheme: light dark.
  2. Preferencia del sistema operativo: Si no existe override manual, el navegador respeta automáticamente prefers-color-scheme.
  3. Override explícito del usuario: Los atributos [data-theme="light"] y [data-theme="dark"] fuerzan el color-scheme correspondiente.
:root {
  color-scheme: light dark;
  --color-bg: light-dark(#f8fafc, #0f172a);
  --color-surface: light-dark(#ffffff, #1e293b);
  --color-text: light-dark(#1f2937, #e2e8f0);
  --color-primary: light-dark(#2563eb, #60a5fa);
}

/* Override manual del usuario mediante atributo de datos */
[data-theme="light"] { color-scheme: light; }
[data-theme="dark"]  { color-scheme: dark; }

5. Taxonomía de Tokens (Escalable a Design System)

Arquitectura en 3 capas: Primitivos → Semánticos → Componentes

/* CAPA 1: PRIMITIVOS (Escala base neutra, nunca se consumen directo en UI) */
--blue-500: #2563eb;
--slate-50: #f8fafc;
--slate-800: #1e293b;
--space-4: 1rem;

/* CAPA 2: SEMÁNTICOS (Decisión de diseño y soporte light/dark) */
--color-primary: light-dark(var(--blue-500), #60a5fa);
--color-primary-hover: color-mix(in srgb, var(--color-primary) 85%, black);
--color-surface: light-dark(#ffffff, var(--slate-800));
--space-card-padding: var(--space-4);

/* CAPA 3: COMPONENTES (Opcional, para librerías multi-marca / white-label) */
--card-bg: var(--color-surface);
--card-padding: var(--space-card-padding);
--card-radius: var(--radius-md);
Checklist de Auditoría

Antes de dar por cerrado un sistema de estilos, verifica tres criterios: 1) ¿Alterna entre light y dark cambiando únicamente data-theme? 2) ¿Al modificar --color-primary se regeneran automáticamente sus variantes suaves y estados hover con color-mix()? 3) ¿Tus gradientes animados utilizan @property?
