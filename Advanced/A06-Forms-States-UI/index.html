Módulo A06 · Forms & Interactive UI States

Formularios y Estados UI

Un formulario moderno no necesita JavaScript para ofrecer retroalimentación inmediata y accesible. Con :user-valid, :user-invalid, :placeholder-shown, :focus-visible, accent-color y controles personalizados con appearance: none construyes experiencias nativas robustas.

1. Pseudo-clases de validación — Feedback sin JS

El navegador evalúa continuamente las restricciones HTML5 (required, type="email", min, pattern). A diferencia de :invalid —que marca error antes de que el usuario empiece a escribir—, :user-invalid y :user-valid esperan a que el usuario haya interactuado con el campo.

Ciclo de vida declarativo de un campo

/* 1. Estado inicial intacto: placeholder visible */
.field:placeholder-shown {
  border-color: #cbd5e1;
}

/* 2. Inválido únicamente tras interacción del usuario */
.field:user-invalid {
  border-color: #dc2626;
  background: #fef2f2;
}

/* 3. Válido tras interacción del usuario */
.field:user-valid {
  border-color: #16a34a;
  background: #f0fdf4;
}

/* 4. Mensaje de error hermano revelado sin JS */
.field:user-invalid ~ .error {
  display: block;
}

2. :focus-visible vs :focus y :focus-within

:focus se activa tanto al hacer clic con ratón como al navegar con teclado. :focus-visible aplica el anillo de foco únicamente cuando el navegador detecta navegación por teclado o entrada de texto, manteniendo la interfaz limpia sin sacrificar accesibilidad.

:focus — Anillo siempre

Muestra el contorno incluso al hacer clic con puntero.

.btn:focus {
  outline: 2px solid #2563eb;
}

:focus-visible — Teclado

Oculto al clic con mouse; visible al tabular con teclado.

.btn:focus-visible {
  outline: 2px solid #2563eb;
}

:focus-within — Contenedor

El contenedor padre detecta cuando cualquier descendiente recibe foco.

.group:focus-within {
  border-color: #2563eb;
}

3. accent-color — Personalización nativa de controles

Una sola declaración tiñe los controles nativos (checkbox, radio, range y progress) con el color de marca, calculando automáticamente el contraste interno y adaptándose al esquema claro/oscuro.

4. Controles custom sin JS — Checkbox, Switch y Radio

Mediante appearance: none eliminas el dibujo nativo del sistema operativo pero conservas intacta la semántica HTML, el estado :checked, el manejo por teclado (Space) y la lectura para tecnologías de asistencia. Nunca ocultes el <input> con display: none.

Checkbox personalizado con appearance: none

.c-check input {
  appearance: none;
  width: 20px;
  height: 20px;
  border: 1.5px solid #cbd5e1;
  border-radius: 5px;
  display: grid;
  place-items: center;
}
.c-check input:checked {
  background: var(--color-primary);
  border-color: var(--color-primary);
}
.c-check input:checked::after {
  content: "✓";
  color: #ffffff;
  font-size: 13px;
}

Interruptor (Switch) accesible con role="switch"

.c-switch input { appearance: none; position: absolute; opacity: 0; }
.c-track {

}
.c-track::after {
  content: ""; position: absolute; width: 22px; height: 22px;
  background: #ffffff; border-radius: 50%; top: 3px; left: 3px; transition: 180ms;

.c-switch input:checked + .c-track { background: var(--color-primary); }
.c-switch input:checked + .c-track::after { transform: translateX(18px); }

Checklist de Accesibilidad (A11y) en Formularios

1. Nunca ocultes controles con display: none; utiliza appearance: none para preservar el árbol de accesibilidad. 2. Mantén siempre visible el anillo :focus-visible en tus controles personalizados. 3. Vincula cada <label for="..."> con su id y añade role="switch" en interruptores binarios. 4. Prefiere :user-valid / :user-invalid para no mostrar errores prematuros.
